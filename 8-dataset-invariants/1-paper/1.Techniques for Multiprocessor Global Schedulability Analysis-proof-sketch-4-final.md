# Prompt used:
ROLE
Assume the role of a real-time systems researcher and Prosa/Coq expert with high code-quality standards.

INPUT

OBJECTIVE
1) Extract only the parts of the paper that can be mechanized and proved in Coq using Prosa.

   B) a single-file Coq/Prosa skeleton that contains ONLY comments (no executable code), showing where each definition/lemma/theorem will go and what to do there.

SCOPE & CONSTRAINTS
- Include ONLY sections that will be converted into a mechanized Coq/Prosa proof of the paper’s main theorems. Omit optional sections or corollaries that are not needed or cannot be fully mechanized.
- Treat everything as a single file (no multi-file layout).
- In the skeleton, DO NOT write imports, definitions, tactics, or any Coq code. Use comments only.
- Modularize aggressively: make building blocks as unit/small as possible.
- Use the exact comment delimiter “====section====” to mark major sections and subsections.
- Use programming-standard variable names (e.g., snake_case; no Greek letters or symbols). Do not copy symbols from the paper.
- Align with Prosa concepts where applicable (tasks, arrivals, schedulers, interference, response time, busy intervals, etc.), but keep everything comments-only in the skeleton.
- Do NOT include a symbol-mapping section.
- Do NOT use “what/why” prose inside the skeleton; use imperative, step-by-step lines as described below.

WHAT TO ANALYZE & DECIDE
- Identify workload, resource, scheduler, and analysis assumptions that MUST be formalized.
- List the theorems/lemmas actually needed for the main results and map their dependencies.
- Specify the definitions/invariants required to bridge the paper and Prosa.
- Propose helper lemmas and intermediate results required to reach each theorem.
- Exclude anything not essential to proving the main theorems mechanistically.

OUTPUT FORMAT
Produce two parts:

PART A — Micro-Task List (Just Steps, In Order)
- Output as a **numbered list** only (Step 1, Step 2, …).
- Each step is a single, imperative sentence, as small as practical (micro-task).

PART B — Single-File Coq/Prosa Skeleton (Comments-Only, Imperative Style)

- Use only comments; no code at all.
- **Every item must be its own section**: each `define`, each `lemma`, each `theorem`, and each **block of variable declarations** appears in a separate comment block starting with `====section==== <unique_name>`.
- Inside each section, write only imperative lines in this style:
  - `define X with parameters a,b,c`
  - `comment: short intent`
  - `declare variable v : type`
  - `perform step …`
  - `perform call to lemma …`
  - `perform combine …`

STYLE
- Be precise, terse, and implementation-oriented so a Coq developer can follow the checklist and then fill in the code exactly where each comment says.
- Do not include any narrative not directly supporting mechanization.

NOW DO IT
